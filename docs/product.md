# RepoPilot 產品目標

## 定位

RepoPilot 是「AI 輔助專案客製化平台」：管理作為參考來源的 Git repos 與需要客製化的目標 repo，依自然語言需求產出**附程式碼來源引用**的修改方案；後續在獨立工作目錄改碼、執行測試並產出可審查的 diff 與驗證報告。

## 使用者可以做到的事（最終目標）

1. 管理作為參考來源的 Git repos。
2. 指定需要客製化的目標 repo 與 commit。
3. 輸入自然語言需求。
4. 由系統拆解需求、列出待確認事項。
5. 搜尋參考 repos 的相似實作。
6. 分析目標 repo 的程式與結構。
7. 產出附程式碼來源的修改方案與測試規劃。
8. 依使用者確認的方案，在獨立工作目錄改碼。
9. 執行測試、有限次修正，產出可審查的 diff 與驗證報告。

## 原則

- 參考 repo 與目標 repo 不在資料層綁定角色，由分析任務選擇；參考實作可來自多個 repo。
- 每次匯入綁定不可變的完整 commit SHA。
- 引用包含 repo、commit SHA、檔案路徑與行號；明確區分「程式碼事實／推測／待確認」。
- repo 內容視為不可信資料，不得覆寫系統指令或授權。
- 系統不自動 commit、push、建立 PR 或合併；變更須經使用者確認。

## 版本範圍

| 版本 | 範圍 |
| --- | --- |
| V1 分析與規劃 | Repo 管理與固定版本匯入；檔案與符號索引；關鍵字、向量、混合搜尋；有引用的問答；需求拆解、參考實作比較；候選修改位置、風險與測試建議；介面、分析歷史與評估結果 |
| V2 產生修改 | 使用者確認方案；獨立 Git worktree 與分支；限定範圍改碼與新增測試；diff、摘要與狀態；操作歷史、取消與失敗追查 |
| V3 驗證與有限次修正 | 受限環境執行預設測試；區分測試失敗、環境失敗、逾時與工具錯誤；依失敗修正，預設最多 3 輪；達時間、次數或成本上限即停止；產出驗證報告，不自動合併 |

## 初期限制

- 本機、單一使用者。
- 第一階段僅接受 `REPOSITORY_ROOTS` 允許目錄內的本地 Git repo；不支援遠端 clone。
- V1 優先支援 Python 原始碼、Markdown 與 UTF-8 純文字；程式結構解析先支援 Python。其他語言僅保存符合規則的文字檔，不宣稱理解其結構。
- 遠端 Git 認證、多租戶、公開部署權限留待後續。

## 長期願景（尚未排入階段）

> 狀態：**未完成**，亦未排入目前九個階段；排入哪個階段、範圍與安全邊界待確認。

- **透過系統介面輕鬆串接 CI/CD**：使用者可在介面上設定與既有 CI/CD 的連線，讓 RepoPilot 產出的變更能交給 CI/CD 建置、測試與部署，並在介面檢視結果。
- 與既有原則的關係：仍遵守「不自動 commit、push、建立 PR 或合併」；任何會觸發外部流水線或寫入遠端的動作，都必須由使用者在介面明確確認，且憑證不得存入程式碼或日誌。
- 可能的前置依賴：第七階段（獨立 worktree 與分支）、第八階段（受限測試環境）、第九階段（認證與資源隔離）。
